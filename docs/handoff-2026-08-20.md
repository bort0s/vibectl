## 4. Open gaps

**`timeout`'s floor is inherited, not derived.** `HOOK_TIMEOUT_SECS = 5`. The
rule has two terms — a ×100 multiplier over steady state and a floor over cold
start — and **the multiplier has never bound**: 37.5 ms × 100 is 3.75 s, under
the floor, so the floor has decided every time. Only `win32-x64` has a cold-start
maximum. **Do not settle this until the CI distribution has samples on all three
platforms**; it accumulates one per push per platform, and pushes have resumed.

**`if`'s control is committed and has never been run.** ADR-0011 §9 makes it
**owed, not waived** — `if` is the sole *exclusion* from the prohibition on
testing omission defaults, so the prohibition does not reach it. The fixture is
`scratchpad/if-omission-control.json`; the invocation and the expected table are
in §9 of ADR-0011. It needs a real Claude Code binary and a live session, so it
cannot run in CI. It measures **somebody else's build**: a red is *upstream
moved*, and the repair is a decision about what install writes, never a code fix
here.

**`USERPROFILE` overrides do not reach the CLI's home resolution, and the cause
is unknown.** Measured four ways on Windows 10 Pro 19045 with `directories`
6.0.0 — forward slashes and backslashes, from Git Bash and PowerShell — and
`prompts::user_home()` returned `None` every time against a directory that
exists, while the unmodified environment resolves correctly. **The reason this is
recorded is the unknown cause, not that it is harmless.** It is harmless *today*
only because `install::plan` and `install::state` take `home` as a parameter, so
all 16 controls plant their own. Anyone driving the **CLI** against a fixture
home hits it, and the failure looks exactly like holding it wrong. What would
close it: measure `BaseDirs::new()` directly under each candidate environment.
Nobody has. Full note in `monitor_install.rs`'s `resolve_ambient` doc.

## 5. The unanswered `--ours` hypothesis

**Recorded because the evidence is perishable and now, finally, is not.**

The `gate.sh` conflict on 2026-08-20 was the *first* conflict on this branch
resolved by reading both sides. Every earlier rebase resolved with
`git checkout --ours <file>` wholesale, on `docs/adr/0001-crate-boundaries.md`
each time. Wholesale `--ours` takes one side of a conflicted file **entirely**,
so if any of those files also carried a change worth keeping from the other
side, it was discarded silently — the same failure mode as `rebase --skip`, one
level down, and it would not appear as a lost commit.

**It is unmeasured.** It may well be nothing: those conflicts were on a document
whose other side was plausibly superseded. The way to answer it is to diff each
backup's version of the conflicted files against the corresponding post-rebase
version and read what left:

```
git diff backup/measure-pre-rebase:docs/adr/0001-crate-boundaries.md \
         backup/measure-pre-rebase-2:docs/adr/0001-crate-boundaries.md
```

- `backup/measure-pre-rebase` (`c123ff7`) — pre-first-rebase, 28 ahead of the
  old base. **Sole copy of its commits**; not an ancestor of the working branch.
- `backup/measure-pre-rebase-2` (`6b3f4e5`) — pre-second-rebase, the one a
  `--skip` loop damaged. **Sole copy of its commits.**
- `backup/measure-pre-rebase-3` (`cdae8d4`) — pre-third-rebase. **Redundant**:
  every commit in it was replayed onto `1f65a6b`, and its content was verified
  present by marker. Kept anyway because it costs nothing; if ref hygiene ever
  matters, this is the one to drop first.

**Deleting these deletes the ability to ask.** Keep them until the question is
answered or is deliberately dropped.

## 6. Environment assumptions that belonged to the dead machine

Everything here was a property of one Windows box and **must be re-measured**
rather than inherited.

- **Host triple `x86_64-pc-windows-msvc`.** This is the reason the sixth
  instrument finding happened: `cargo clippy` compiles for the host, so every
  `#[cfg(unix)]` block was stripped before clippy saw it, and the local gate
  reported `clippy 0` for 48 commits while CI's ubuntu leg was red on
  `plan.rs:454`. **A new machine has a different blind spot, not none.**
- **Toolchain: `rustc 1.97.1 (8bab26f4f 2026-07-14)`, `clippy 0.1.97`, resolved
  through the rustup shim to
  `~/.rustup/toolchains/stable-x86_64-pc-windows-msvc/bin/`.** CI pins
  `toolchain: stable`, so a new machine on a later stable may differ from what
  is recorded here. `cargo-clippy` on `PATH` is a **shim**; `which` cannot
  answer which binary ran, `rustup which` can.
- **`scratchpad/gate.sh` covers cross-COMPILATION and not cross-EXECUTION.**
  Clippy runs for three OS families (`host` bare, plus `--target
  x86_64-unknown-linux-gnu` and `--target x86_64-apple-darwin`) under CI's exact
  flags. `cargo test` is **host-only and cannot be otherwise** without a machine
  of that OS. On a new host the *set of untested `cfg` bodies changes*, and the
  gate names them — re-read its comment rather than assuming the same three.
  `aarch64-apple-darwin` was unusable there because blake3 1.8.6's build script
  compiles NEON C and no cross `cc` existed; that may not hold elsewhere.
- **The three target stds must be installed** or the cross legs go red with an
  instruction. `rustup target add x86_64-unknown-linux-gnu x86_64-apple-darwin`,
  plus `--toolchain 1.85.0 x86_64-unknown-linux-gnu` for the MSRV step.
- **`gh` was NOT installed.** No CI log was ever read from that machine; every
  statement about a run's existence was inference, and one such inference
  reached a session report as fact before being retracted. On a machine with
  `gh`, read the run instead of reasoning about it.
- **git authorship cannot distinguish participants.** Every commit is
  `unknown <riccardobortos0@gmail.com>` whoever made it. Author metadata is not
  an attribution source here — see ADR-0002 §7.

## 8. Next: ADR-0011 §8's display — and read ADR-0009 first

**Deliberately not started on 2026-08-20.**

ADR-0009's constraints were written for the deferred Tauri GUI. **This is their
first real consumer**, so they are read before anything is built rather than
recalled. Read from the source on 2026-08-20 — the full set is **nine**, and a
six-item summary circulating in conversation omitted two that are load-bearing:

**§3 — hold under any style**

- **a. One visual mark per row, not a composition per project.** With 34
  projects, legibility is the binding constraint. A row is scanned, not read.
- **b. Colour encodes status; opacity encodes staleness of the last commit.**
  Two channels, two variables, and **neither is available for anything else** —
  no colour for emphasis, no opacity for hierarchy.
- **c. Honest detection survives into the UI.** A stack that was not inferred is
  an empty field *flagged as not-detected*. No placeholder, no `Unknown` where a
  value goes, no greyed-out guess. *"We did not detect this"* and *"this project
  has no stack"* are different facts and must not render the same.
- **d. Core mute, frontend speaking.** `vibe-core` produces no prose.

**§4 — what the types already force**

- **`Status` has six cases, not five.** `Other(String)` exists so a future
  build's value round-trips. A five-colour palette is not a complete mapping, and
  **an unrecognised status must not borrow one of the five** — that is exactly
  the 2026-08-11 defect where an unknown `Severity` rendered as `warning`. The
  sixth case must read as *"this build does not recognise this value"* and must
  **not** read as an error, because it is not one.
- **Staleness can be absent.** *(Omitted from the summary — do not skip it.)*
  `ProjectSummary::last_commit` is an `Option`. A project whose last commit could
  not be read has **no position on a fresh-to-stale scale**, and rendering it at
  either end is invention. Absence needs its own treatment, distinct from both
  "fresh" and "stale".
- **An unreadable project is a row, not a gap.** `ProjectSummary::error` is
  populated when the manifest could not be read, and ADR-0002 §3 requires the
  project to still appear. A third visual state, and the one that *is* an error.
- **`archived` is orthogonal to `status`.** *(Omitted from the summary — do not
  skip it.)* Every combination is legal; `shipped + archived` and
  `dead + archived` are different states. Archived is a **second dimension** and
  cannot be folded into the status colour without destroying information the
  manifest deliberately keeps separate.
- **`from_cache` is not staleness.** The flag means the row came from the cache
  whose witness matched — the value is still believed correct. Conflating it with
  commit staleness reports a fact about *our read* as a fact about *the project*.

§8 also records two things the display inherits and cannot fix: §5's retraction
means an open `tool_use_id` supports **nothing** about the present, and §7a's
transport makes history a **partial order**, so the display inherits an
*unordered with respect to each other* state it may not render as a sequence.
